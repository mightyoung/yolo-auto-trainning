## Papers

### arXiv:2305.10601 — Tree of Thoughts
- Core idea: replace single linear CoT with explicit search over candidate "thought" states plus self-evaluation and backtracking.
- Best fit: bounded planning/search tasks with small branching factor and cheap verification.
- Main cost: latency and orchestration complexity rise quickly if applied to every request.

### arXiv:2303.11366 — Reflexion
- Core idea: capture task feedback as verbal reflections in episodic memory and feed them into later retries.
- Best fit: repeated trial-and-error loops with measurable task outcomes.
- Main cost: memory quality drifts if reflections are noisy, duplicated, or ungrounded.

### arXiv:2602.07398 — AgentSys
- Core idea: isolate worker contexts from the main agent and pass only schema-validated outputs upward.
- Best fit: tool-heavy agents exposed to untrusted external content.
- Main gain: reduced prompt-injection surface and less memory pollution.

### arXiv:2604.02268 — SKILL0
- Core idea: internalize external skill files into model behavior through curriculum + RL, reducing runtime skill retrieval.
- Best fit: organizations training or fine-tuning their own agent models at scale.
- Main cost: high training complexity and weak immediate applicability for inference-only systems.

### arXiv:2601.03236 — MAGMA
- Core idea: represent memory as multiple orthogonal graphs (semantic/temporal/causal/entity) instead of one flat store.
- Best fit: long-horizon agents that must retrieve structured historical evidence.
- Main cost: substantial data-modeling and retrieval-system overhead.

## Project context

- Business API now has cleaner task registry and route handler split, but `business-api/src/agents/orchestration.py` remains the dominant orchestration hotspot.
- Training execution was split heavily; `training-api/src/training/runner.py` is now thin, with curriculum/transfer/yolo modules extracted.
- Security and configuration improved, but the agent path still mixes tool execution, remote operations, memory/state propagation, and policy decisions.
- The system is mostly workflow orchestration plus training automation, not a general autonomous agent platform.

## Preliminary fit assessment

- Strong fit:
  - Reflexion for bounded retry memory on failed or plateaued training/export tasks.
  - AgentSys for isolating external tool outputs and remote-operation traces from top-level agent memory.
- Partial fit:
  - Tree of Thoughts only for specific planning nodes such as remediation-plan generation, not for general request handling.
  - MAGMA only as a lightweight event graph over task history, not as a full multi-graph memory subsystem.
- Weak fit:
  - SKILL0, because this repo is not currently training agent policies/models; it orchestrates external LLM calls and ML jobs.

## Likely recommendations

- Introduce typed "attempt memory" for retries and postmortems rather than free-form long prompts.
- Isolate worker/tool contexts from top-level orchestration state and pass only validated summaries.
- Keep planning search explicit and narrow; do not wrap every operation in ToT-style branching.
- Do not build a heavy graph-memory stack until the project has clear long-horizon retrieval failures.
